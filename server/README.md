# سرور پرداخت نخل جیرفت (درگاه زیبال)

این پوشه، بخش سرورِ پرداخت است. **گیت‌هاب نمی‌تواند PHP را اجرا کند**، پس این فایل‌ها فقط وقتی کار می‌کنند که آن‌ها را روی یک **هاست ایرانی با PHP** بگذارید. تا آن موقع، سایت در «حالت آزمایشی» کار می‌کند و پول واقعی جابه‌جا نمی‌شود.

## چه کاری انجام می‌دهد؟

خریدار هیچ‌وقت شماره‌ی کارت را روی سایت ما وارد نمی‌کند. مسیر این است:

۱. سایت سفارش را به `pay-request.php` می‌فرستد.
۲. این فایل از زیبال یک `trackId` می‌گیرد و خریدار را به **صفحه‌ی امن خودِ بانک** می‌فرستد.
۳. خریدار شماره‌ی کارت، رمز دوم/پویا و… را **روی صفحه‌ی بانک** وارد می‌کند (نه روی سایت ما).
۴. بانک خریدار را به سایت برمی‌گرداند و سایت `pay-verify.php` را صدا می‌زند.
۵. `pay-verify.php` با زیبال چک می‌کند که پرداخت واقعاً موفق بوده؛ آن‌وقت سفارش «پرداخت‌شده» می‌شود.

این سرور هیچ اطلاعات کارتی را نمی‌بیند و ذخیره نمی‌کند — فقط شماره‌ی کارتِ ماسک‌شده (مثل `۶۲۷۴****۱۲۳۴`) که خود زیبال برمی‌گرداند.

## راه‌اندازی (گام‌به‌گام)

۱. در `zibal.ir` ثبت‌نام کنید و برای دامنه‌تان **مرچنت‌کد** بگیرید (به اینماد و دامنه‌ی ثبت‌شده نیاز دارد).
۲. کل این پوشه‌ی `server` را روی هاست آپلود کنید، مثلاً در `public_html/api/`.
۳. فایل `config.php` را باز کنید و سه مقدار را درست کنید:
   - `merchant` → مرچنت‌کد واقعی که از زیبال گرفتید.
   - `callback_url` → آدرس کامل سایتتان (همان جایی که `index.html` باز می‌شود).
   - `allow_origin` → آدرس سایتتان بدون اسلشِ آخر.
۴. مطمئن شوید پوشه‌ی `data` قابل نوشتن است (`chmod 770`). سفارش‌ها اینجا ذخیره می‌شوند.
۵. در فایل `js/app.js` سایت، یک خط را پیدا کنید:
   ```js
   const PAY = { api: '', merchant: 'zibal' };
   ```
   و `api` را برابر آدرس همین پوشه بگذارید، مثلاً:
   ```js
   const PAY = { api: 'https://nakhljiroft.ir/api', merchant: 'zibal' };
   ```
   همین که `api` پر شد، سایت از حالت آزمایشی خارج می‌شود و خریدار به درگاه واقعی بانک می‌رود.

## نکته‌های امنیتی مهم

- **`config.php` را روی گیت‌هاب یا جای عمومی نگذارید**؛ مرچنت‌کد واقعی در آن است. فقط روی هاست خودتان.
- پوشه‌ی `data` با فایل `.htaccess` از دسترسی وب بسته شده است. اگر هاستتان آپاچی نیست (مثلاً nginx)، خودتان جلوی دسترسی مستقیم به `data/` را بگیرید.
- **مبلغ قابل اعتماد نیست:** الان مبلغ از سمت مرورگر می‌آید. برای امنیت کامل، `pay-request.php` باید مبلغ را از روی قیمت واقعی محصولات *روی سرور* دوباره حساب کند، نه اینکه به عددِ آمده از مرورگر اعتماد کند. (در کد با کامنت مشخص شده.) فعلاً به‌عنوان محافظ، مبلغی که بانک در گام تأیید برمی‌گرداند باید دقیقاً با مبلغ ثبت‌شده یکی باشد.
- سفارش‌ها فعلاً در فایل‌های JSON داخل `data/` ذخیره می‌شوند. برای فروشگاه جدی بهتر است بعداً به دیتابیس (MySQL) منتقل شوند تا پنل مدیر هم سفارش‌های همه را از سرور بخواند (نه فقط از مرورگر خودش).
